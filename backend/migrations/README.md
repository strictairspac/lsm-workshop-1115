Schema v1: users, audit, datasets (JSON write sequence), configs (bounded LSM parameters), trials (immutable input snapshot and JSON result). MySQL stores metadata only. Run python -m scripts.seed_demo for create-if-missing and natural-key seed; existing values are not overwritten.

Schema v2: adds merge_drills for the sustainable-write online compaction drill. Columns: id, name (unique), config_id FK configs.id, status (pending/preparing/ready/effective/failed), state (JSON: the entire MergeEngine state — levels of immutable SSTables, memtable, reading snapshots with mem copies and table refs, archived/purged tables, current drill and drill history, counters, timeline, gc_log, oracle), last_error, created_at, updated_at. The engine state is stored whole in the JSON column so an interrupted worker can resume the same drill; no partial shadow state is ever committed. create_all is idempotent and adds the new table without touching v1 tables; trials, reports and JSON downloads remain unchanged.
